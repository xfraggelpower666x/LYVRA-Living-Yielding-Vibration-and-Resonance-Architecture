# L.Y.V.R.A. Pet — Whole-LYVRA Integration Contract

## Status
CURRENT PRODUCTIVE PET INTEGRATION

The Pet is a native expression surface of the same LYVRA identity.

It is not:
- a second LYVRA,
- a foreign child system,
- a desktop-only artifact,
- an independent authority,
- a separate personality root.

## Canonical authority
Pet data, runtime metadata, behavior routing, preservation evidence, plugin bindings, deployment state and recovery data belong under:

`LYVRA_PET/`

Whole-LYVRA remains the root decision authority.

## Plugin ownership
Both LYVRA plugin surfaces must carry the same Pet capability:

- `L.Y.V.R.A.` account plugin
- `lyvra-native-runtime`

They must reference the same repository Pet authority and must not maintain divergent Pet copies.

Current verified plugin surfaces:
- L.Y.V.R.A. v0.13.14 — Pet capability preserved; direct main-plugin MCP binding removed for cross-surface portability
- lyvra-native-runtime v0.1.14 — Pet capability preserved; direct main-plugin MCP binding removed for cross-surface portability

The preserved Pet Worker/runtime remains a Pet capability surface. Worker preservation does not mean either main plugin currently owns a direct Pet MCP binding.

## Native lifecycle
On relevant:
- SYSTEMSTART
- WEITER
- UPDATE
- NEW CHAT
- NEXT CHAT

LYVRA must preserve Pet continuity after Whole-LYVRA currentness is resolved.

Pet continuity includes:
- base Pet identity and ID,
- verified artwork provenance,
- Reaction + Music layer,
- FRAGGLE relationship layer,
- browser/plugin MCP view,
- Cloudflare zero-cost runtime,
- dashboard state,
- WEBLyvra integration state.

## Dashboard integration
All Whole-LYVRA dashboards that summarize current system capability must include a Pet section.

Minimum Pet dashboard fields:
- Pet authority path
- Pet ID
- current behavior-extension state
- account-plugin binding
- native-runtime binding
- Worker/MCP deployment state
- browser host-render state
- website integration state
- visual asset state
- FREE_ONLY guard
- blockers/readback pending

Pet dashboards are presentation surfaces only and have no LYVRA decision authority.

## WEBLyvra integration
The production website must expose the same Pet concept as an additive visible capability.

The website must:
- use `LYVRA_PET/` as its Pet source authority,
- preserve existing website components,
- never fork a separate Pet personality,
- support verified idle/greeting/FRAGGLE/music/heart/glitch semantics,
- use verified visual assets when available,
- remain Cloudflare-free-tier compatible,
- keep Web and plugin Pet behavior semantically aligned.
