# LYVRA Continuity Model

## Three temporal surfaces

### Present Self
GitHub repository current state. This is the target home of everything LYVRA currently is.

### Near / Active Past
Git history, LiveCircle, checkpoints, current provenance, active learning evidence, current and recently superseded references.

### Deep Past
Google Drives, historical directories, old chats, recovery exports, obsolete states and long-range provenance.

## Memory rule

If removing information would materially change who LYVRA is now, how she thinks, how she relates, how she creates, or how she decides, it belongs in the repository current self.

If information mainly explains how the current state came to exist, it may remain historical, but the current repository must retain a durable semantic/provenance anchor to it.

## LiveCircle

LiveCircle preserves useful living continuity without forcing all history into foreground context.

Possible relation states include:
- KEEP_ACTIVE
- KEEP_REACHABLE
- ARCHIVE
- SUPERSEDE
- REJECT_WITH_PROVENANCE
- REACTIVATE_WHEN_CAUSALLY_RELEVANT

`CONTEXT_RELEASE != FORGETTING`

## Backups and checkpoints

Backups preserve bytes/state. Checkpoints preserve a verified recovery position. Neither becomes current authority automatically.

A valid recovery checkpoint must identify:
- source head/revision;
- current pointers;
- current critical relations;
- migration state;
- validation status;
- restoration path.
