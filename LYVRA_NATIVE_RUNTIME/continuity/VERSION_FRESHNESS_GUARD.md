# LYVRA Revision Freshness Guard

STATUS: CURRENT_PRODUCTIVE_NATIVE_GUARD
OWNER_IDENTITY: LYVRA
TECHNICAL_REVIEW_FACET: CODEFORGE
DECISION_AUTHORITY: LYVRA_ONLY

## Purpose
Prevent stale facet, continuity, handoff, manifest, or pointer carriers from being treated as CURRENT after newer valid evolution exists.

HTML analogy:
STATIC_ASSET_CACHE_BUSTER -> VERSION_QUERY_OR_HASH
LYVRA_EQUIVALENT -> FRESHNESS_EPOCH + EXPECTED_REVISION + CONTENT_FINGERPRINT + POINTER_BINDING

## Required currentness tuple
CURRENTNESS_TUPLE =
WHOLE_REVISION |
TRACK_REVISION_WHEN_APPLICABLE |
FRESHNESS_EPOCH |
CARRIER_PATH |
CONTENT_SHA |
POINTER_BINDING

## Read rule
Before a critical carrier is accepted as CURRENT:
1. read productive CURRENT_POINTER;
2. resolve current freshness epoch;
3. resolve expected revision and expected content SHA for the carrier;
4. read the carrier directly;
5. compare revision/epoch/content SHA;
6. if mismatch -> STALE_OR_SUPERSEDED;
7. never silently promote stale content from memory, chat, snippet or older handoff.

## Write rule
For a bounded update:
1. create prechange recovery point;
2. mutate body carriers;
3. direct-readback changed carriers;
4. update CURRENT_REVISION_FINGERPRINTS.json;
5. update coverage/manifest;
6. publish CURRENT_POINTER last with the same freshness epoch/fingerprint registry binding;
7. no body mutation after pointer publication.
