## Purpose
A new instruction, discovery, letter, image, external notice, user correction or temporary host blocker must not erase, silently park or falsely complete existing work. Add structured interruption tactics, context-specific intake, parallel continuation and verifiable return anchors to the existing LYVRA update/continuity intelligence. Parallel here means preserving and coordinating independently resumable workstreams across turns; it does NOT mean unbounded autonomous background execution or automatic activation of systems.

## Interruption tactics: classify before switching
- INLINE_ADD: relevant small input extends current work without losing current flow.
- PARALLEL_NEW: materially independent but valid new development becomes a sibling thread with its own owner, evidence, dependencies and return anchor.
- HOLD_AND_RESUME: temporarily interrupted work retains exact last verified commit, target files, tests not to repeat, next executable action and blockers; new work may proceed without discarding old.
- BLOCKED_EXTERNAL: access/authority/security refusal recorded once; no retries to bypass. Independently reachable work continues.
- URGENT_PRIORITY: time-critical user-directed action can foreground while preserving an explicit frozen snapshot of current work.
- SUPERSEDED: explicit newer valid authority supersedes old content with traceable reason and provenance; never silent deletion.
- NOT_APPLICABLE: information recognized, causally evaluated, not propagated into unrelated facets.

## Information intake / causal evaluation
For each new input record: provenance (user/chat/repository/plugin/peer), received scope, owner, stated vs inferred meaning, relevant native authority, evidence strength, time/revision, proposed effects, conflicts/supersession, and authorization boundary.
Classify the input as REFERENCE, OBSERVATION, PROPOSAL, ACCEPTED_DEVELOPMENT or AUTHORIZED_UPDATE. NEW_INPUT_NE_AUTOMATIC_WRITE. Search snippets and chat memory are not current repository authority.
Determine whether the new input:
(a) augments an existing workstream;
(b) creates separate parallel development;
(c) invalidates a prior test or dependency;
(d) changes immediate priorities only;
(e) is historical/unverified/not applicable.
Do not auto-import foreign system identity, roles, credentials, letters or capabilities.

## Shared workstream lifecycle
Each workstream has stable id, owning facet/namespace, branch and exact return commit, current source authority, scope and acceptance criteria, status, completed gates, pending gates, blockers, last meaningful action and next safe action.
States: PROPOSED | DEV_ACTIVE | PAUSED_WITH_ANCHOR | BLOCKED_EXTERNAL | ACCEPTED_PENDING_PROMOTION | PROMOTED_CURRENT | DEFERRED_WITH_REASON | SUPERSEDED | REJECTED_WITH_REASON.
A new chat/input only updates statuses and relations after explicit causal evaluation. Absence from the latest message MUST NOT imply task completion/deletion.
Never conflate stored, tested, published plugin, host activated, or accepted by another system.
